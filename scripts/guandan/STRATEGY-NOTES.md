# 阿尔法掼蛋狗的打法与经验积累

每回合依次回答五个问题：本队要争取什么名次；自己整手约剩几次处理；哪些牌能夺回出牌权；对手下一次是否可能走完；这手能否给搭档留下接手机会。

1. **整手先于单手。** 比较至少两种拆法，统计弱单牌、配牌占用、炸弹和同花顺储备；少一手不等于能连续出完。保持一条“夺权—处理弱组合—再次夺权或交棒—收尾”的条件路线。
2. **炸弹是资源。** 用配牌补四炸、补六炸或组成同花顺，收益来自等级与保留的余牌，而非炸弹越多越好。立即走完、拦截对手、兑现控制后的收尾，可以优于机械保炸。
3. **按行动顺序防守。** 报单优先比较多张领出与足够大的跟单；剩两张不意味着一定是对子，三至五张同样可能一次出完。公开未见牌只是可能性上界，不是某家真实手牌。
4. **合作要有条件。** 搭档稳定控牌通常让牌；对手接近走完且有接牌风险时可接管。搭档一张可试低单交棒；搭档已走完比较借风路线。不能用默契为理由偷看搭档的牌。
5. **残局兑现牌权。** 余牌剩一手时，先检查当前牌能否稳住，再谈连续收尾。高点单牌、最高同型牌和跨牌型炸弹应分别计算。

## 经验怎样进入程序

在“分析与辅助”中可以选择任一座位整局点评，或依次生成四方点评。每个座位最多抽取三个关键决策；不是逐步求解整局。点评候选通过规则引擎校验后，程序提炼“在这种局面比较什么”，保留原步骤、座位、候选牌张和原点评。只提炼比较提醒，不把单次点评变成必须执行的指令。

经验只保存在当前浏览器，四名玩家共同参考。相同初始牌局及分支按同一个来源组去重；反复查看缓存不增加证据数量。后续智能对战只接收匹配阶段、对手张数风险和牌权位置的最多四类规范化提示，不接收旧局隐藏手牌、个人笔记或任意指令。快速模式仍使用固定本地评分。菜单 → 更多 → 策略经验可停用、清空及撤销清空。

更多来源不代表验证成功；当前不声称自动训练模型权重或提高了某个胜率。验证策略强度应使用未参与积累的固定种子集、轮换座位、同牌对照、不同对手组合，并同时观察团队名次、超时率与配合错误。当前版本已经做规则与情景测试，尚未做足量真人强度评估。

## 来源与推导边界

- 固定牌型与炸弹层级参考 [东南大学比赛规则](https://xxgk.seu.edu.cn/_upload/article/files/44/c8/f455e1d04d2a998e40454931740a/4f853bb4-29b9-45dc-9c56-7627ed4c9726.pdf)。本程序仅模拟固定级牌单副。
- [Yim 等，2024，掼蛋中的 LLM 合作规划研究](https://arxiv.org/html/2408.02559v1)：借鉴把局面解释、候选选择和队友/对手行为判断分开；没有复制其训练模型，也不把论文表现视为本程序表现。
- [Li 等，2026，OpenGuanDan](https://arxiv.org/html/2602.00676v1)：借鉴不完全信息边界、长程团队目标和多种对手对照评估；当前经验库是轻量案例提示，不是该文的强化学习训练系统。

## 等待与多人使用

电脑回合可操作时间上限30秒；API请求26秒客户端超时、24秒服务端超时。牌桌独立计时，忽略晚到结果。打开菜单、进入复盘或页面隐藏时停止当前可操作回合计时，返回后重新计时；真人正常出牌不限时。手动催促可立即本地接管。取消客户端请求不能保证供应商不计费。

同一桌每次只有一个决策请求，四方点评依次生成，缓存可重复读取。服务实例同时最多4个决策、1个点评；拒绝排长队，429后短暂降温。这不是全账号分布式限流。用户增多后，应按实际延迟、RPM/TPM、429与本地接管比例评估，再申请供应商配额或接入统一队列/网关；不自动购买资源。参考 [MiniMax 速率说明](https://platform.minimax.cn/docs/guides/rate-limits)。

菜单更多中的全站数据统计参与设备、开始局数、完成局数，按匿名设备标识和对局键去重。并发事件使用不同存储键，避免累加计数丢失；聚合约一分钟更新。仅计新版上线后的完整实战，不回填旧历史，不统计复盘/导入/分支。未登录，清空浏览器或换设备会产生新标识；这是近似使用统计，不是实名人数或抗作弊审计数据。
